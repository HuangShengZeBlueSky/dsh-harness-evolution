# 复现什么，以及怎样运行

本仓库分开提供 **已经测过的 Harness 产物**、**可选择策略的进化代码**、**原实验配置与结果**。三者相互对应，但不是“安装后一个命令重现所有历史分数”。原实验有不同起点、划分、优化器和预算；插件有效也不等于它会被下一次搜索再次发现。

| 目标 | 已公开 | 仍需准备／边界 |
|---|---|---|
| 理解或加载五场景最终产物 | 插件、组合、框图、协议、曲线；见 `harnesses/` | 模型服务和对应环境；启动服务不等于完成评测 |
| 新跑 DBBench／WebShop／OSBench 的 L1–L9 | `evolution/` 公共运行层、策略、36份配置、固定任务编号、评分桥接 | 数据、数据库／购物服务／任务镜像，做题与优化模型资源 |
| ALFWorld 历史方法 | 最终产物、任务/结果记录、实际环境适配器 | 原搜索流程未迁入这36份配置；通用 ALFWorld inventory 不是历史109题测试集 |
| Telecom 历史方法 | 最终产物和双角色桥接集成，详见原运行说明 | 匹配 Tau2 扩展、GLM 用户、账户事实与复核权限；未统一到单执行器循环 |
| 新摘要／机制反馈循环 | `evolution/extensions/feedback/` 的真实核心、十组提示、原生宿主参考 | 独立历史接入；可移植端到端运行未验证，不能直接作为 L7 配置启动 |
| 早期 Skill／Workflow 与经验实验 | 方法与历史结果说明 | 不冒充同一份 DSH 代码的开关消融，也未在此包重跑 |

## 一、先运行最小例子

需要 Python 3.10 以上、Node.js 22.19 以上。按源码工作区使用可编辑安装；`profiles/` 与适配器随仓库保留，不提供独立 wheel 安装承诺。

```bash
cd evolution
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python scripts/smoke.py ./workspaces/demo
```

例子使用脚本模型与预先写好的插件，真实经过 DSH 钩子、L7 的准备、计划、评测、晋升与最终测试。**它验证安装和运行链，不测试真实模型能力，也不证明优化器能自主发现该插件。** 首次执行通过 npm 安装模板中固定版本的 DSH 依赖；不调用做题或优化模型 API。

本次发布已走通这一条链：4个训练场次、2个验证场次、2个测试场次；候选的拒绝／恢复钩子确实改变下一动作。没有重跑36组正式实验。初始化路径与全部配置静态核对，真正场景环境仍依赖下述资源。

## 二、运行一个新实验

以下示例启动新的 OSBench L7；这会调用模型和任务环境。先准备任务环境，再运行；不要指向旧实验输出目录。

```bash
cd evolution
source .venv/bin/activate
export BENCH_BASE_URL=http://localhost:8000/v1
export BENCH_CHAT_URL=http://localhost:8000/v1/chat/completions
export BENCH_TOKENIZER_URL=http://localhost:8000/tokenize
# 如服务需要认证，设置 BENCH_API_KEY。
dsh-evolve init ./workspaces/os-l7 \
  --profile osbench-l7-sol61 --assets /data/os-assets
# 查看生成的 experiment.yaml，确认模型、数据、Docker地址和预算。
dsh-evolve setup ./workspaces/os-l7/experiment.yaml
dsh-evolve run ./workspaces/os-l7/experiment.yaml
```

`init`复制配置、提示、固定任务编号和运行模板；从 asset 目录挂载数据。DB/OS小体积原评分源码随包提供，除非 asset 目录显式提供自己的 `source/`。`run`先评测基线，再保持优化器会话；门槛在策略代码执行。`status`读取当前选择与决定数。全部轮次决定完成后，`finish`先封存选择再测试，测试不进入下一候选。

三个 URL 是连接配置，必须指向同一做题模型及其 tokenizer。YAML 中的 `${环境变量}` 在运行时解析；模型名称、温度、输出预算、任务清单和策略仍由 YAML 保存。公开配置记录 `Qwen3-4B-Instruct-2507` 做题、`gpt-6.1-sol` high 优化；替换不可用模型可以运行新实验，但不能称为原模型复现。Codex 优化器和 L8/L9 学习调用均需自己的有效登录和模型权限。

### 场景资源

| 场景 | asset 内容和服务 | 保留的关键语义 |
|---|---|---|
| DBBench | MySQL 8.4；`pip install -e '.[dbbench]'`；asset含 `data/db_out_new.jsonl` 与 `data/standard.jsonl` | 15次模型调用；32,768上下文；4,096输出；SQL初始化与评分原逻辑；连接在 `mysql_host/mysql_port/mysql_password_env` 配置 |
| WebShop | 与原协议对应的商品与目标数据；提供 `/reset`、`/step`、`/close` 的服务；设置 `WEBSHOP_URL` | 20次模型调用/工具步；严格买对与平均奖励分列；每次reset创建会话 |
| OSBench | Docker；asset含 `fixtures/{train,test}/*.json` 与匹配的 `os-evolve/*` 任务镜像 | 16次模型调用/工具步；工具回执800字符协议；原匹配/脚本评分 |
| ALFWorld | 官方游戏数据及 `alfworld==0.4.2`、TextWorld 1.7.0、spaCy 3.7.5、NumPy 1.26.4等 | 当前公开适配器保留可行动作与动作映射；不要换成通用示例后声称同一环境 |

评分源码在 `evolution/benchmark_sources/`，许可证随附。数据集、数据库和镜像不在Git里。任务编号相同不保证商品索引、数据库内容、任务镜像或评分源码相同，替换资产要作为新协议记录。

## 三、每个策略究竟改什么

| 策略 | 原代码的选择／额外输入 | 运行入口 |
|---|---|---|
| L1 | 同批训练严格改善，验证不退步，真实改动生效 | `loops/l123.py` |
| L2 | L1加固定训练子集总分不降；**并非仅回放父版成功题** | `loops/l123.py`、`loop_policy.py` |
| L3 | 最多三个验证较好分支，优先访问次数少的父版；保留分支不等于更换冠军 | 同上 |
| L4 | 先维护当前插件职责/能力，再提案；只有配置了验证集时才检查验证 | `loops/l45.py` |
| L5 | DB下一批不退步；Web按严格成功选择；OS验证类别宏平均不退步 | `loops/l45.py` |
| L6 | 计划先于编码；完整同批严格成功改善、计划内改动实际使用；没有独立验证门槛 | `loops/l6.py` |
| L7 | L6加完整失败索引分类、独立验证与对应场景门槛 | `loops/l789.py` |
| L8 内部／外部 | 在L7基础上，逐轮学经验／先学整个旧实验并固定指导本次 | `loops/l789.py`、`learning.py` |
| L9 | 在L7基础上，读取已有训练选定插件目录，按当前失败组装和改造 | `loops/l789.py` |

实际继承为 `Project → L1–3 / L4–5 / L6 → L7–9`，不是 L1→L9 完整逐层继承。下表是**训练任务数＋独立验证任务数**；配置信息也可直接读取 [profile-index.json](../evolution/profile-index.json)。

| 场景 | L1–L3 | L4 H0 | L5 H0 | L6 | L7–L9 | 最终测试 |
|---|---|---|---|---|---|---|
| DBBench | 240＋60 | 300＋0 | 240＋60 | 300＋0 | 300＋60 | 300题×3 |
| WebShop | 240＋60 | 300＋0 | 240＋60 | 300＋0 | 300＋60 | 200题×3 |
| OSBench | 80＋20 | 80＋20 | 83＋17 | 300＋0 | 300＋60 | 144题×3 |

DB/Web按六批训练；OS L1–L5为固定集合，L6–L9六批训练。每轮父版和候选在同批比较，不能把不同批次的原始分数串成固定测试集上的单调进步。全部公开三场景配置40个新候选；“从旧最佳续跑”还带有先前搜索成本。测试seed是任务/重复身份，配置 `send_seed: false` 时不会将其发送给模型端点，不能承诺模型输出完全确定。

### 有先验的方法需要提供什么

`l4-best`／`original-best` 初始化需 `--baseline /path/to/training-selected-harness`。L8外部的 `loop.experience_sources` 必须是已完成的训练工作目录，包含决定与可读训练轨迹；空目录不能算“已有经验”。L9需 `--components` 指定训练选定的历史产物；历史训练材料可附到目录索引。替换成测试最高产物会改变先验条件。学习调用、旧搜索成本和失败重试应另计。

## 四、复现记录与发布口径

一份结果至少对应：配置、任务清单、环境版本、初始产物、优化器/做题模型/用户模型、预算、每轮父版与采用决定、完整有效评测、最终冻结选择和对应测试。保留运行时输入/控制证据、修复与回退，不能只保留最终百分比。进化过程的日志留在自己的工作目录，公开发布紧凑统计即可。

指标分开记录：候选数、采用数、冠军变化数、任务与重复场次数、均值与每次结果、有效/无效/重试、同任务修复/回退、模型请求/输出token/墙钟时间。没有的指标用缺失值；独立搜索次数不能用同一检查点的测试重复次数替代。成本缺失的历史结果不能作等预算胜出结论。

本次代码整理只统一入口、连接配置和包内依赖，删去弃用的单模块入口；保留策略与评分差异。最小链通过并不证明完整包在五场景获得原分数。真正复现应使用新工作目录、同配置和环境重新运行，并发布新的结果记录。
