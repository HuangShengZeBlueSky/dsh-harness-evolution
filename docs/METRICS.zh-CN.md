# 指标、进化记录与比较口径

[English](METRICS.md) | **简体中文**

先看**哪一个实验、怎样选出的检查点、在哪些任务上测了几次**，再看分数。[公开数据](../results/research/README.md)把这些信息对应起来；未知值保留为空，不填零。

## 分数与重复稳定性

| 指标 | 定义与用途 |
|---|---|
| 严格成功率／Pass@1 | 有效场次中成功的比例；WebShop要求原生奖励恰为1 |
| 平均奖励 | 原生奖励的平均值；WebShop可部分得分，不能替代严格购买成功 |
| 每次重复成绩 | 分开报告各次成功数、有效场数、成功率和平均奖励 |
| 重复间标准差 | 已观察到的几次成绩的总体标准差，单位为百分点；不是独立搜索的不确定性 |
| 观察到的三次至少一次成功 | 同一任务三次中至少一次成功的任务比例；仅三次完整时计算 |
| 观察到的三次全部成功 | 同一任务三次均成功的任务比例；与上一项不同，不以平均成功率的三次方替代 |
| 有效／缺失／无效尝试 | 最终覆盖与结果账本中的无效记录分开统计；不宣称覆盖其他位置未保存的全部重试 |

每组当前只有一次独立进化搜索，三次任务测试不是三个搜索种子。逐任务数值结果在 `results/research/test-outcomes/`，不含对话或模型请求正文。任务重复、优化器重复与模型温度是不同概念。

**实例：**OS机制反馈平均成功32.87%，高于摘要反馈29.40%；三次全部成功却为25.00%，低于26.39%。三次至少一次成功为40.28%对32.64%。本次观察是成功覆盖扩大而重复稳定性未同步提高，不能据单次搜索推出普遍优势。

## 每轮到底记录什么

每个候选记录父版、轮次、训练批次、同批父版和候选成绩、验证、采用或拒绝、冠军是否改变，以及存在时的配对修复／退步。L3“保留进分支库”与“成为冠军”不同。

开发曲线和测试点分面呈现。训练批次可能轮换，连线不是固定题集的学习曲线；未测检查点不生成测试值。WebShop训练平均奖励与严格成功分别保留；L5的采用目标看显式 `training_strict`、`validation_strict`，不能看奖励均值猜测。

目标问题修复与整体修复分开。有候选整体涨分却没修好原计划目标，这不否定实测涨分，但不能证明预先的解释。请求中出现提示、插件产生事件、运行器执行控制分别是观测，不是收益证明。

## 时间与成本

模型请求数、环境动作数、插件事件数、实际控制回执与每场耗时均从已有结果记录聚合，并带观测覆盖。场次耗时求和是并发任务的累计工作量，不是墙钟耗时；首末采用决定间隔不含启动和最终测试，也不是完整实验成本。没有用配置并发数估算吞吐或费用。

优化器与学习调用的Token总量尚未统一汇总，所以保持为空。复用L4/L5经验和组件的L8/L9有历史先验成本，不能算作免费从零搜索；论文成本列也保留其原计量范围。

## 选择与比较

每组 `final_selection` 原样保留其训练／验证规则选出的最终检查点。主榜从多个实验挑出表现好的产物，已经使用测试结果进行跨实验选择；回溯补测也是观察过测试后的发现。两者都不是一场新的盲测。公开产物分为 `training_final` 与 `retrospective_adopted`，后者附真实采用记录。

当前主线的数据协议存在差异：DB/Web的L4为300训练、无独立验证，L5为240训练加60验证；OS的L4为80加20，L5为83加17。L6无独立验证，L7–L9各自有300训练加60验证。因此，L1–L9不是一次严格单变量递增消融。[逐配置矩阵](../evolution/profile-index.json)保留精确身份。

论文参考来自[Life-Harness v3](https://arxiv.org/html/2605.22166v3)表1、10、11；其他方法也是该论文作者报告的结果，不是我们的重跑。论文的优化器、六轮预算、测试次数及部分任务划分与我们不同。Telecom还存在用户模拟器、账户事实与辅助复核接口差异。

公开Life-Harness内置实现的GLM用户复测为基线37/120、full69/120；历史DSH H0的52/120是另一运行条件，分别记录。官方说明区分[内置实现与各次进化得到的最终bundle](https://github.com/Tianshi-Xu/Life-Harness/blob/main/TauBench/README.md)，因此该复测不等于取得并复测了论文90分产物。

## 如何复算

`results/research/collect.py`读取指定实验根的原生配置、决定和结果，只导出数值统计及配置，不启动实验。每条公开记录有相对实验标识、检查点、任务编号、trial和seed。历史只有曲线而配置未找全的条目标记为 `curve_only`，不会用当前配置倒填历史。

完整运行依赖、原始模型身份、已验证的运行链及仍缺的历史接入见[复现说明](REPRODUCING.zh-CN.md)。代码整理后的离线示例通过，不代表所有公开历史分数已经用新包重新测过。
