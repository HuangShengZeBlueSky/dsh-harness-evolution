# L6：归因、能力状态、修复插件与真实效果

目标是在既定训练数据和预算内，把反复出现的失败变成可复用能力。一个问题类别可以对应一个或多个插件，多个类别也可以共享能力；不为数量、格式或覆盖率凑数。

每轮先 prepare。它先取得当前父版在本轮完整训练批次的结果，并提供 agent-inventory.json 与训练失败索引。阅读父版实际源码、相关失败完整轨迹、匹配的成功对照；不要仅看分数、末尾错误或自动提取的钩子名。按导致行为失败的原因聚类，区分上游缺失状态与下游报错。不能确定时把判断写成假设。

写插件前，在 analysis.json 简明回答：当前 Agent 如何执行、已有插件解决什么、状态由谁维护和消费、从哪次真实回执更新和失效、当前问题为什么仍未解决。每类问题列出代表性训练任务及消息位置；说明原能力不足还是能力之间冲突。随后把归因映射到一个或一批插件，写清预期触发条件、状态变化、动作变化及可能受损的成功案例。先运行 plan 记录计划，再实现插件。

analysis.json 格式示意（占位内容必须换成本轮真实证据；不要求固定字数、类别数、插件数）：

    {"parent":"baseline","agent_state":"现有执行流程、能力、状态所有者与缺口",
     "clusters":[{"id":"问题类别","hypothesis":"原因假设及替代解释",
       "members":["本轮训练任务编号"],"controls":[],
       "evidence":[{"task_id":"本轮训练任务编号","message_index":0,"observation":"此处发生了什么，为什么支持假设"}]}],
     "repairs":[{"cluster_id":"问题类别","plugin_ids":["插件标识"],
       "operation":"add / modify / remove / combine，说明实际改法",
       "hooks":["实际接通的钩子"],"trigger":"从什么可见证据判断应该介入",
       "state_change":"状态的来源、所有者、更新、使用、清除；无状态则说明",
       "expected_behavior":"预计改变哪个真实动作或提交","at_risk_tasks":[]}]}

任务编号与消息位置只用于离线归因，不允许作为插件题号分派或答案。测试、验证轨迹不得用于设计。问题类别允许重叠；覆盖率只用于暴露盲区，绝不作为采用分数。

实现可以增加、改写、删除或组合插件。优先让每个插件承担清楚职责；必要时共享状态，明确写入、读取、更新及清除顺序。允许从历史未采用版本学习失败原因，但不复制其他实验组新发现或测试反馈。针对明确证据修复，不做无限文案改写或无关检查。插件使用本场景已接通 DSH 接口，保持原生工具、任务、评分、模型、预算不变。

实现后 evaluate 真跑本轮完整训练，再 report。报告分别统计插件加载、自报钩子事件、真实模型输入命中、运行器控制回执、动作序列变化、修复和退步任务；它们不是同一个指标。无触发先区分条件未出现、注册失效、状态未更新或事件没有记全，不把增加审计日志当作修复。出现行为差异也不自动证明因果；读取关键配对轨迹判断变化是否沿预期路径发生。

采用条件：同批完整训练严格成功率提高，已计划的改动确实进入输入或控制路径。WebShop 主要指标为 score==1 的严格成功，平均奖励为辅助。运行器验证真实输入/控制证据；插件自述触发不能单独满足采用。纯删除修改需确认被删除能力在父版实际运行，删除后完整评测获益。单轮多个插件的联合收益不拆成各插件独立贡献。

复盘时维护 progress.txt：归因是否得到支持；哪些类别修复、哪些成功案例退步；是否存在重复指导、状态冲突或误触发；下一轮应该延续机制还是换解释。每轮不要求大报告；用可定位的事实表达。

三个场景使用公开复现流程的六批50道训练任务，循环至40轮；测试集不变，每题三遍。H0从零开始，Sol6.1 high负责进化，Qwen3-4B-Instruct-2507做题。这是我们的40轮扩展实验，不冒充论文原优化器/六轮预算。全部40轮决定后，仅测试最终训练选定检查点。
